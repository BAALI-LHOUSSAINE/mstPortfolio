Sockets TCP & Sniffing de paquets avec Scapy

Comprendre en profondeur comment les communications réseau fonctionnent au niveau des sockets, comment capturer et analyser les paquets TCP en temps réel avec Scapy, et interpréter le three-way handshake à travers une implémentation concrète en Python.

// 01 — INTRODUCTION

Pourquoi analyser le trafic réseau ?

Dans le domaine de la sécurité informatique, comprendre les communications réseau à bas niveau est une compétence fondamentale. Que l'on soit administrateur système, analyste SOC, pentesteur ou simple développeur curieux, savoir capturer, inspecter et interpréter les paquets qui transitent sur un réseau est indispensable.

Cet article explore deux axes complémentaires : d'abord la programmation de sockets TCP en Python pour établir des communications réseau, puis l'utilisation de Scapy — une puissante bibliothèque Python — pour sniffer et analyser ces paquets en temps réel. L'association des deux permet de visualiser concrètement ce qui se passe "sous le capot" de chaque connexion réseau.

Objectif pédagogique

À la fin de cet article, vous serez capable de créer un serveur/client TCP en Python, de capturer les paquets associés avec Scapy, et d'interpréter les flags TCP pour comprendre l'état d'une connexion.

Éthique & Légalité

Le sniffing réseau est une technique puissante qui doit être utilisée uniquement sur des réseaux dont vous avez l'autorisation explicite d'analyser. Intercepter des communications sans autorisation est illégal dans la plupart des pays. Toutes les démonstrations de cet article s'effectuent en localhost (127.0.0.1), dans un environnement contrôlé.

// 02 — FONDEMENTS

Le modèle TCP/IP : rappels essentiels

Avant de plonger dans le code, il est crucial de comprendre les couches réseau impliquées dans nos échanges. Le modèle TCP/IP (ou modèle Internet) organise les protocoles réseau en 4 couches distinctes, chacune ayant un rôle précis.

4
Application HTTP, FTP, SSH, DNS — nos données applicatives
Message
3
Transport TCP / UDP — segmentation, fiabilité, ports
Segment
2
Internet IP, ICMP — adressage et routage
Paquet
1
Accès réseau Ethernet, Wi-Fi — transmission physique
Trame

Dans notre implémentation, nous opérons principalement aux couches Transport (TCP, via les sockets) et Internet (IP, via Scapy qui inspecte les en-têtes IP et TCP).

TCP vs UDP : pourquoi choisir TCP ?

TCP (Transmission Control Protocol) est un protocole orienté connexion qui garantit la livraison des données dans l'ordre. Il utilise un mécanisme de confirmation (ACK) et de retransmission. À l'opposé, UDP (User Datagram Protocol) est plus rapide mais sans garantie de livraison. Pour notre démonstration, TCP est idéal car il génère un échange de paquets riche et observable.

Caractéristique TCP UDP
Connexion Orienté connexion Sans connexion
Fiabilité Garantie Non garantie
Ordre des données Préservé Non préservé
Vitesse Plus lent Plus rapide
Usage typiqueHTTP, SSH, FTPDNS, VoIP, jeux
// 03 — SOCKETS PYTHON

Programmer des sockets TCP en Python

Un socket est une interface de programmation (API) qui permet à deux processus de communiquer via un réseau. En Python, le module socket de la bibliothèque standard expose cette interface de manière simple et portable.

Un socket TCP se caractérise par un tuple (adresse_IP, port). Le serveur écoute sur un port donné, tandis que le client initie la connexion depuis un port éphémère attribué automatiquement par l'OS.

Le serveur TCP

Le serveur suit un cycle de vie précis : créer le socket → lier à une adresse/port → écouter les connexions entrantes → accepter un client → recevoir les données → répondre → fermer.

Python — server.py 
import socket
import threading

# Constantes de configuration
HOST = '127.0.0.1'  # Écoute uniquement en local
PORT = 5000        # Port d'écoute du serveur

def handle_client(conn, addr):
    """Gère la communication avec un client connecté."""
    print(f"🔗 Client connecté : {addr}")
    with conn:
        while True:
            data = conn.recv(1024)   # Buffer de 1024 octets
            if not data:
                break
            message = data.decode('utf-8')
            print(f"📩 Reçu : {message}")
            # Accusé de réception applicatif
            conn.sendall("ACK".encode('utf-8'))

def start_server():
    # AF_INET = IPv4 | SOCK_STREAM = TCP
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        # Permet la réutilisation immédiate du port (évite "Address already in use")
        s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
        s.bind((HOST, PORT))
        s.listen(5)  # File d'attente de 5 connexions max
        print(f"🌐 Serveur TCP lancé sur {HOST}:{PORT}")

        while True:
            conn, addr = s.accept()  # Bloquant — attend une connexion
            # Thread séparé par client pour gérer plusieurs connexions
            t = threading.Thread(target=handle_client, args=(conn, addr))
            t.daemon = True
            t.start()

if __name__ == '__main__':
    start_server()

Le client TCP

Le client est plus simple : il crée un socket, initie la connexion vers le serveur (ce qui déclenche le three-way handshake), envoie des données et attend la réponse.

Python — client.py 
import socket

HOST = '127.0.0.1'
PORT = 5000

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.connect((HOST, PORT))   # Déclenche le 3-way handshake !

    while True:
        msg = input("Message : ")
        if not msg:
            break
        s.sendall(msg.encode('utf-8'))
        response = s.recv(1024).decode('utf-8')
        print(response)   # Affiche "ACK" du serveur

Paramètres du socket expliqués

  • AF_INET — Famille d'adresses IPv4 (utiliser AF_INET6 pour IPv6)
  • SOCK_STREAM — Type TCP (flot d'octets ordonné et fiable)
  • SO_REUSEADDR — Réutilise le port même en état TIME_WAIT
  • recv(1024) — Taille du buffer de réception en octets
// 04 — PROTOCOLE TCP

Le Three-Way Handshake : établissement de connexion

Avant d'échanger le moindre octet de données applicatives, TCP établit une connexion via un mécanisme en 3 étapes : le three-way handshake. Ce processus permet aux deux parties de synchroniser leurs numéros de séquence (SEQ) et d'établir un canal bidirectionnel fiable.

Client 127.0.0.1:62152
SYN Seq=0 — "Je veux me connecter"
Flags: S 56 bytes
"OK, et toi synchronise-toi" SYN-ACK
Flags: SA 56 bytes
ACK Seq=1, Ack=1 — "Confirmé !"
Flags: A 44 bytes
PSH+ACK "Hello Yasuo" — données envoyées
Flags: PA 55 bytes
Accusé réception des données ACK
Flags: A 44 bytes
Serveur 127.0.0.1:5000

Décryptage des flags TCP

Chaque segment TCP contient un champ de 6 bits de contrôle appelés flags. Ils définissent la nature et l'état du segment. Voici les flags observés dans notre capture :

SYN

Synchronize

Initie une connexion TCP. Le premier paquet envoyé par le client. Contient le numéro de séquence initial (ISN).

Flags: S
SYN-ACK

Synchronize + Acknowledge

Réponse du serveur au SYN. Il accepte la connexion et envoie son propre numéro de séquence.

Flags: SA
ACK

Acknowledge

Confirme la réception d'un segment. Présent dans quasiment tous les paquets après l'établissement de la connexion.

Flags: A
PSH

Push

Demande à l'OS de transmettre immédiatement les données au processus destinataire sans attendre de remplir le buffer.

Flags: PA
FIN

Finish

Initie la fermeture de la connexion. Chaque côté envoie un FIN pour terminer proprement.

Flags: F
RST

Reset

Réinitialisation forcée de la connexion. Utilisé en cas d'erreur ou de refus de connexion.

Flags: R
// 05 — SCAPY

Scapy : la boîte à outils réseau Python

Scapy est une bibliothèque Python incontournable dans le domaine de la sécurité réseau. Elle permet de créer, envoyer, capturer et analyser des paquets réseau avec une flexibilité remarquable. Contrairement à des outils comme Wireshark (GUI), Scapy s'intègre dans des scripts Python pour automatiser l'analyse.

Le sniffing de paquets nécessite un accès bas niveau à l'interface réseau. Sur Windows, lancez votre script en tant qu'Administrateur. Sur Linux/macOS, utilisez sudo python script.py ou accordez les capabilities réseau : sudo setcap cap_net_raw+eip /usr/bin/python3

Comprendre la fonction sniff()

La fonction centrale de Scapy pour la capture est sniff(). Elle accepte de nombreux paramètres permettant de cibler précisément les paquets qui nous intéressent.

Python — Anatomie de sniff() 
from scapy.all import sniff, TCP, IP

sniff(
    filter="tcp and port 5000",  # Filtre BPF : uniquement TCP sur le port 5000
    prn=analyse_packet,             # Callback appelé pour chaque paquet capturé
    store=False,                   # Ne pas stocker en mémoire (mode streaming)
    iface=None,                    # None = toutes les interfaces
    count=0,                        # 0 = capturer indéfiniment
    timeout=None                    # None = pas de timeout
)

Les filtres BPF

Scapy utilise la syntaxe BPF (Berkeley Packet Filter) pour les filtres, la même que tcpdump et Wireshark. Ces filtres s'appliquent au niveau du kernel pour des performances optimales.

"tcp" Tous les paquets TCP
"tcp and port 5000" TCP sur le port 5000 uniquement
"host 127.0.0.1" Trafic vers/depuis 127.0.0.1
"tcp and port 5000 and host 127.0.0.1" Combinaison avec opérateurs logiques
"not port 22" Tout sauf le port SSH
// 06 — IMPLÉMENTATION COMPLÈTE

Application GUI : Sockets & Sniffing intégrés

Voici l'implémentation complète de l'application démontrée dans les captures d'écran. Elle combine un serveur TCP, une interface graphique Tkinter et un sniffer Scapy, le tout exécuté via des threads pour rester réactif.

Python — main_app.py (Application complète) 
import socket
import threading
import tkinter as tk
from tkinter import scrolledtext
from scapy.all import sniff, TCP, IP

# ─── Configuration ───────────────────────────────────────
HOST = '127.0.0.1'
PORT = 5000

# ─── Interface Graphique ──────────────────────────────────
root = tk.Tk()
root.title("Analyse Réseau - Sockets & Sniffing")
root.geometry("900x620")
root.configure(bg='#1a1a2e')

FONT = ('Courier New', 10)
BG   = '#16213e'
FG   = '#e0e0e0'

# Zone messages socket
tk.Label(root, text="=== Messages Socket ===",
         font=FONT, bg=BG, fg='#00ff6a').pack(fill='x', padx=5)
msg_box = scrolledtext.ScrolledText(
    root, height=10, font=FONT, bg=BG, fg=FG, state='disabled')
msg_box.pack(fill='both', expand=True, padx=5, pady=2)

# Zone paquets sniffés
tk.Label(root, text="=== Paquets Sniffés ===",
         font=FONT, bg=BG, fg='#00e5ff').pack(fill='x', padx=5)
sniff_box = scrolledtext.ScrolledText(
    root, height=15, font=FONT, bg=BG, fg=FG, state='disabled')
sniff_box.pack(fill='both', expand=True, padx=5, pady=2)

# ─── Fonctions utilitaires ────────────────────────────────
def log(widget, msg):
    """Ajoute un message dans une zone de texte (thread-safe)."""
    widget.config(state='normal')
    widget.insert(tk.END, msg + '\n')
    widget.see(tk.END)
    widget.config(state='disabled')

def get_flags(tcp_flags):
    """Convertit les flags numériques en notation lisible."""
    flags = ''
    if tcp_flags & 0x02: flags += 'S'   # SYN
    if tcp_flags & 0x10: flags += 'A'   # ACK
    if tcp_flags & 0x08: flags += 'P'   # PSH — avant ACK pour avoir PA
    if tcp_flags & 0x01: flags += 'F'   # FIN
    if tcp_flags & 0x04: flags += 'R'   # RST
    return flags or '?'

# ─── Serveur TCP ─────────────────────────────────────────
def handle_client(conn, addr):
    log(msg_box, f"🔗 Client connecté : {addr}")
    with conn:
        while True:
            data = conn.recv(1024)
            if not data: break
            log(msg_box, f"📩 Reçu : {data.decode('utf-8')}")
            conn.sendall("ACK".encode('utf-8'))

def start_server():
    log(msg_box, "🌐 Serveur TCP lancé...")
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
        s.bind((HOST, PORT))
        s.listen(5)
        while True:
            conn, addr = s.accept()
            threading.Thread(
                target=handle_client, args=(conn, addr), daemon=True
            ).start()

# ─── Sniffer Scapy ───────────────────────────────────────
def analyse_packet(pkt):
    """Callback appelé par Scapy pour chaque paquet capturé."""
    if pkt.haslayer(TCP) and pkt.haslayer(IP):
        ip  = pkt[IP]
        tcp = pkt[TCP]
        flags = get_flags(int(tcp.flags))
        size  = len(pkt)

        line = (
            f"🔎 {ip.src}:{tcp.sport:8}"
            f" → {ip.dst}:{tcp.dport:8}"
            f" | TCP | {size:4} bytes"
            f" | Flags: {flags}"
        )
        root.after(0, lambda l=line: log(sniff_box, l))

def start_sniff():
    log(sniff_box, "🔍 Sniffing TCP actif...")
    sniff(
        filter=f"tcp and port {PORT}",
        prn=analyse_packet,
        store=False
    )

# ─── Lancement des threads ────────────────────────────────
threading.Thread(target=start_server, daemon=True).start()
threading.Thread(target=start_sniff,  daemon=True).start()

root.mainloop()

Architecture multi-threads

L'application utilise 3 threads distincts pour éviter tout blocage de l'interface :

  • Thread Principal — Boucle d'événements Tkinter (interface graphique)
  • Thread Serveur — Écoute et accepte les connexions TCP entrantes
  • Thread Sniffer — Capture passive des paquets avec Scapy

La méthode root.after(0, lambda...) permet de mettre à jour l'interface depuis un thread secondaire de manière thread-safe.

Interprétation détaillée

1–3

Three-Way Handshake (paquets 1 à 3)

Les trois premiers paquets constituent l'établissement de la connexion TCP. Notez que les paquets SYN et SYN-ACK font chacun 56 bytes (en-têtes IP + TCP avec options MSS) alors que l'ACK nu ne fait que 44 bytes (sans options additionnelles). La connexion est pleinement établie après le 3ème paquet.

4

Envoi de données — PSH+ACK (paquet 4)

Le flag PSH (Push) combiné à ACK indique l'envoi du message "Hello Yasuo". Le flag PSH force l'OS à transmettre immédiatement les données au processus destinataire sans attendre d'accumuler plus de données dans le buffer. La taille de 55 bytes inclut les 11 caractères de "Hello Yasuo" plus les en-têtes TCP/IP.

5

Acknowledgement des données (paquet 5)

Le serveur accuse réception des données applicatives avec un ACK pur (44 bytes). À ce stade, le serveur a reçu le message mais n'a pas encore envoyé sa réponse applicative "ACK".

6

Réponse du serveur — PSH+ACK (paquet 6)

Le serveur envoie la réponse applicative "ACK" (3 bytes de données). Le paquet fait 47 bytes soit 3 bytes de plus que l'ACK nu, ce qui correspond exactement à la chaîne "ACK" en ASCII.

7

ACK final du client (paquet 7)

Le client confirme la réception de la réponse du serveur. L'échange est complet. La connexion reste ouverte pour d'éventuels messages suivants.

// 08 — CONCLUSION

Conclusion & Perspectives

À travers cet article, nous avons exploré l'ensemble du cycle de vie d'une communication TCP : depuis la programmation des sockets en Python jusqu'à la capture et l'analyse des paquets avec Scapy. La corrélation entre le code applicatif et les paquets réseau observés permet de comprendre concrètement ce qui se passe à chaque niveau du modèle réseau.

Points clés à retenir

  • Le module socket Python expose une interface simple pour créer des connexions TCP/UDP
  • Tout appel à connect() déclenche automatiquement un three-way handshake TCP
  • Les flags TCP (SYN, ACK, PSH, FIN, RST) définissent l'état et la nature de chaque segment
  • Scapy permet de capturer et d'analyser ces paquets en temps réel avec une grande flexibilité
  • Un paquet ACK nu fait toujours 44 bytes (14 ETH + 20 IP + 20 TCP) en IPv4 sur Ethernet
  • Le multi-threading est indispensable pour combiner serveur, sniffer et interface graphique
